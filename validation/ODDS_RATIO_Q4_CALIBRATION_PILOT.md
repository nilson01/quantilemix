# Four-level marginal odds-ratio timing pilot

This is the 20-case timing and software pilot for [the advance protocol](ODDS_RATIO_Q4_CALIBRATION_PROTOCOL.md), not the protected interval study. Its purpose is to check that the runner, saved-record audit and proposed resource bounds work before any 4,000-case run. The [fixed installed-R comparisons](ODDS_RATIO_RESULTS.md) remain separate evidence.

The pilot generated five independent 500-row datasets in each of four cells, with 200 fixed-cut row resamples per dataset: 4,000 bootstrap fits in total. All 20 package fits succeeded with no recorded warnings. An independent logistic-score checker paired all 20 cases and every resample, found zero issues, and had maximum absolute numerical difference `2.0538126754843233e-11`. A standard-library-only summary calculation found zero summary differences. The pilot's cellwise coverage values are not reported as performance findings; five cases per cell cannot estimate 95% coverage usefully.

The local Mac run used one numerical thread, Python 3.14.3, NumPy 2.5.4 and SciPy 1.18.1. The runner took 3.36 seconds wall time, with 98,353,152 bytes maximum resident memory. The independent checker took 1.40 seconds, with 194,871,296 bytes maximum resident memory. Both reported zero swaps. The saved pilot, audit, aggregate, journal and receipt together occupy 292 KiB. The fresh data-volume check before execution found 63,118,812 KiB available. The pilot source was an uncommitted working tree at parent commit `6be3b943a94987be05d2aaf7e8404e341279e0e4`; the runner records exact source hashes and the audit verifies them. This is acceptable for a pilot, but the protected study requires clean committed source.

Local pilot records are retained outside this repository. The pilot JSON SHA-256 is `2dbde3b5a049ba8c21384cd0f8659d155d7c939028af395bbe4f93121b6fb412`; audit JSON is `7735a775f8173997dce1dcb50ce06af1303916cd5f71f1459f3a490797378dea`; independent aggregate JSON is `c2a9db72e55412da95059532cc1414d7357c9a9e05b322c82eed31d45215cf11`. The journal and completion receipt are retained beside them.

A simple linear extrapolation from 20 to 4,000 cases gives about 11 minutes for the runner and 5 minutes for the checker on this machine. That is only a planning estimate: server versions, storage and scheduling differ, and other studies took longer. Before a protected study, complete the protocol review, confirm its null/non-null target and failure rules, commit clean source, and prepare a bounded server job from current quota and queue evidence. No protected study was launched by this pilot.
