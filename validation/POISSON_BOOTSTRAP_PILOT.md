# Marginal Poisson bootstrap timing pilot

The reviewed `poisson-bootstrap-known-scores-v1` design ran first as a 20-dataset engineering pilot. Each dataset had 500 rows, four prequantized exposure scores, one adjustment covariate and 200 row-bootstrap draws. The pilot was planned before the full study and its coverage rates were not used to change the grid.

The first local pilot completed 20/20 datasets in 1.914 seconds of runner time. Its independent score-equation audit compared both methods in all 20 datasets (40 pairs), with zero package failures, captured warnings or independent failures. The largest absolute numerical difference was `7.34e-12`. Maximum resident memory measured by `/usr/bin/time -l` was 99,565,568 bytes for the runner and 217,186,304 bytes for the checker; its raw result was 153,174 bytes. After protocol-review repairs, a second local pilot completed the same planned 20 identities in 1.856 seconds with the strengthened audit passing all 40 pairs; its raw result was 153,260 bytes. The first pilot's memory measurement is not a separate measurement of the repaired code. These are observed measurements, not server limits.

Server pilot Slurm job `2905497` used source commit `453a1bc5e2f08789077f3c8064d0063ffd6db83a`, Python 3.11.5, NumPy 2.0.0 and SciPy 1.14.0, one CPU, one numerical thread, a 1 GiB request and a five-minute limit. It completed `0:0` in 22 seconds. The runner reported 8.543 seconds and the checker 2.549 seconds. All 20 datasets and 40 pairs passed; the maximum difference was `7.34e-12`. Total pilot output was 94 KiB. The bundle SHA-256 was `51141fee64a888db34baf32b3aa87f455e72e479eeff720d4d54b2a219092334`; the server `result.json` SHA-256 was `89c5894467e28befa0b2a20dce66e969c1ffe746ee4871cfb0d52a9f8c536756`, and `check.json` was `d2b68ca37420154a1a467224d1b49b9da4b349dd2faeac71812cabcaad29b8c7`.

This pilot showed that the pipeline and audit can run on the server. Linear scaling from the measured server time suggested roughly 37 minutes for the 4,000-dataset runner plus checker, so the final study job uses a one-hour time limit. This is a planning estimate, not a study result. The full result requires its own all-case audit and separate interpretation review.

All 20 regenerated input hashes and bootstrap seeds matched between local NumPy 2.5.4 and server NumPy 2.0.0 in this pilot. The full random streams and all future NumPy releases were not checked across versions, so the formal checker still requires an exact NumPy-version match.
